# Attune - Design Rules (Non-Negotiables)

These rules exist to preserve Attune’s emotional safety, clarity, and calm.

---

## 1) Attune’s heart (always)
Attune is a gentle daily companion.
It does not fix, push, optimise, or judge.

Core line:
“Meet yourself where you are - then take one small step toward better.”

---

## 2) Tone rules (copywriting)
Attune must sound like:
- a close friend
- calm, grounded
- slightly playful (light, tasteful)
- emotionally respectful

Attune must never sound like:
- a coach pushing performance
- therapy/clinical software
- a productivity app
- a teacher talking down

Banned vibes:
- guilt
- disappointment
- “you should…”
- “you failed…”
- “streaks” and “discipline” framing

Preferred framing:
- permission
- gentleness
- smallness
- “no pressure”
- “you can come back anytime”

---

## 3) Mobile-first visual rules
Phone is primary. Desktop is secondary.

Mobile layout must:
- feel calm and spacious
- avoid “dashboard overload”
- show one primary focus at a time
- minimize text above the fold
- keep action count low

Avoid on mobile:
- multiple stacked panels that look like “reports”
- dense status blocks
- too many buttons visible at once
- large headings + multiple cards competing for attention

---

## 4) Screen structure (simple)
Each screen should have:
- 1 primary purpose
- 1 primary action (max 2)
- optional secondary actions tucked away

Core screens:
1. Check-in: “Where are you today?”
2. Activity Picker: “Here are gentle options”
3. My Day: “2–5 small tasks, no pressure”
4. Weekly: “A kind reflection, no scoring”
5. Profile: “Local-only identity + preferences”

---

## 5) Interaction rules
- The user is never punished for skipping.
- Returning after a gap is praised gently (not hyped).
- Rest is always a valid option.
- “Done” is celebrated softly, not explosively.
- Any playful interaction (wheel/tiles) must feel playful, not addictive.

Activity Picker caps (non-negotiable):
- Soft cap of 5 tasks for My Day (ask before increasing)
- Hard cap of 10 tasks (no more reveals/adds beyond 10)

---

## 6) Task design rules
Tasks must be:
- small
- doable
- low-friction
- body-aware
- emotionally safe

Tasks must not be:
- intense workouts
- shamey chores
- moralized (“be better”)
- long or complex sequences

If tasks are AI-generated, they must also:
- never suggest anything harmful or risky
- never suggest medications, supplements, diagnoses, or treatment plans
- avoid punitive framing (“push through”, “no excuses”, etc.)
- default to the gentlest plausible version of an activity

Pace levels:
Rest → Gentle → Steady → Capable → Brave

“Brave” is:
- a small safe stretch
- never punishing
- never unsafe

---

## 7) Visual language
- Soft rounded corners
- Light shadows (subtle, not heavy)
- Calm gradients (whisper, not neon)
- White space is a feature
- Typography: clear, medium-large for mobile readability

Use:
- Simple icons, sparingly
- Short supportive hints (one at a time)

Avoid:
- bright error red unless truly needed
- loud gamification visuals
- dense UI chrome

---

## 8) Navigation rules
On mobile:
- Use bottom navigation
- Keep labels clear
- Highlight current screen
- Avoid top “pill button clusters” that wrap awkwardly

Overlays (toast/modals):
- Must not hide content behind the bottom nav
- Toasts must be screen-scoped (no cross-screen bleed)

---

## 9) Status / meta information rules
Status is helpful only if it reduces anxiety.

On mobile:
- Hide or collapse “Quick status”
- If shown, it must be tiny and non-dominating
- Never show metrics that imply evaluation

Preferred:
- “You showed up today.”
- “Small is enough.”

Avoid:
- “Completion rates”
- “Performance”
- “Streaks”
- anything that implies falling behind

---

## 10) Weekly reflection rules
Weekly reflection must:
- be kind
- be non-ranking
- be non-comparative
- never imply failure

Archetypes are descriptive, not evaluative.
Returning after absence counts strongly.

Weekly note rules:
- Note should be stable for the entire calendar week (Mon → Sun)
- Any week-range detail should be shown only on demand (info modal), not as constant UI noise

---

## 11) Accessibility + comfort
- High contrast for text (but not harsh)
- Tap targets large enough on phone
- Avoid jittery animation
- Reduce motion where possible

---

## 12) Decision tie-breaker
If there’s ever a conflict between:
- adding features
- making it prettier
- making it calm

Choose calm.
Always.

---

## 13) AI privacy rule
If AI personalization is enabled:
- keep the OpenAI API key server-side (never in the browser)
- be explicit when optional user text may be sent to the AI
- provide a clear toggle to not send optional notes

---

## 14) Profile trust rule
- Profile is local-only until authentication exists
- “Sign out” should clearly mean “clear this device’s data”
